# HaIT (하잇) 설계 문서 v2

작성일: 2026-09-10
상태: 확정 (v1 `2026-09-09-carbot-design.md`의 도메인을 자동차 → 폰·노트북·데스크탑으로 바꾼 개정판. 엔진·진행 방식·깃 운영은 v1과 같고, 정형 데이터·계산·비전·파인튜닝 일부가 바뀜)

## 1. 한 줄 정의

폰·노트북·데스크탑 이름을 대거나 박스·설정 화면을 찍으면, 한국·영어 리뷰어들이 뭐라 했는지(타임스탬프 링크), 공식 스펙 비교, 실구매가(지원금·선택약정)를 한 화면에 보여주는 로컬 RAG 서비스. 이름은 "동하의 IT"에서 왔다. 표기는 항상 `HaIT`(소문자 `hait`는 패키지명에만).

## 2. 목적과 제약

- 목적: AI 개발자 직무 포트폴리오. RAG, 벡터DB, LoRA·임베딩 파인튜닝, 멀티모달 검색, 평가 리포트를 한 프로젝트에 담는다.
- 사용자 조건
  - 유료 AI API를 쓰지 않는다. 임베딩, 리랭커, LLM, OCR, 비전 전부 로컬.
  - 핵심 로직은 직접 구현한다. LangChain 계열은 비교 챕터에서만.
  - RAG와 파인튜닝은 반드시 들어간다.
- 환경: M2 Pro 16GB, macOS. 기간 8주, 주 15시간. 2026-09-10 시작.
- 재미 요건: 사용자가 IT 유튜브를 즐겨 보고, 신형 아이폰 출시 직후라 앞으로 8주 동안 리뷰가 쏟아진다. 본인이 궁금한 질문이 곧 테스트다.
- 왜 자동차에서 바꿨나: 사용자 관심이 전자기기 쪽이 더 크다. 코드가 없는 시점이라 전환 비용이 문서 수정뿐이었다.

## 3. 범위

### 3.1 들어가는 것

| 기능 | 설명 |
|---|---|
| 리뷰 검색 | 한국·영어 유튜브 리뷰 자막을 타임스탬프 단위로 색인. 한국어 질문으로 영어 리뷰도 찾는 교차언어 검색. 신형·구형이 섞이지 않게 게시일 부스트 |
| 스펙 비교 | 제조사 공식 스펙표를 정규화해 두 기기 이상을 표로 비교. 결정적 답 |
| 실구매가 계산 (폰) | 출고가, 통신사별 지원금, 선택약정 25% × 24개월, 요금제 월액을 넣어 24개월 총비용을 경로별로 비교. 노트북·데스크탑은 공식 출고가만 |
| 신제품 레이더 | 전파인증(적합성평가) 통과 기기 목록. "인증 났는데 아직 안 나온 기기" |
| 리콜 | 소비자24 가전·정보통신 리콜 목록. 모델 매칭 시 표시 |
| 답변 생성 | 로컬 LLM이 근거(한·영)와 스펙·가격 표를 인용해 한국어로 답변. 문장마다 근거 링크 |
| 환각 검증 | NLI로 문장별 근거 여부 판정. 근거 없는 문장 표시·재생성 |
| 프레임 검색 (비전) | 영상 장면 전환마다 프레임을 뽑아 이미지 임베딩으로 색인. "카메라 비교 장면 찾아줘" 같은 시각 질의. 자막 청크와 같은 벡터DB |
| 모델 확정 (비전) | 박스·라벨·설정 화면 사진을 OCR해 모델명을 확정. 확실할 때만 확정 |
| LoRA 파인튜닝 | RAFT 방식으로 학생 모델 학습. 전후 환각률·인용 정확도 비교 |
| 임베딩 파인튜닝 | bge-m3를 리뷰 도메인 질문-청크 쌍으로 추가 학습. 전후 Recall@5 비교(한→한, 한→영) |
| 평가 리포트 | 검색·링크·스펙·가격·프레임·답변 지표를 명령 하나로 마크다운 생성 |
| 배포 | LLM 없이 동작하는 1층을 무료 호스팅에. LLM은 있으면 사용, 없으면 폴백 |

### 3.2 빠지는 것

- 중고 시세, 벤치마크 점수(Geekbench 등은 약관상 수집 안 함), 통신사 요금제 전체 DB(요금제 월액은 사용자 입력).
- 제품 외관 사진으로 모델 식별(폰끼리 너무 비슷하고 학습 데이터셋이 없음. OCR로 대체).
- 자막 원문 재배포(로컬에만 저장, 결과에는 짧은 발췌와 링크만). 유튜브 기계번역 자막 사용 안 함.
- 사진 저장(처리 후 즉시 폐기).

## 5. 구조

### 5.1 모듈

| 모듈 | 하는 일 | 입력 → 출력 | 직접 구현 | 라이브러리 |
|---|---|---|---|---|
| `ingest` | 수집 | 자막, 스펙, 지원금, 전파인증, 리콜 → `data/raw/`. 이미 받은 건 건너뜀 | 수집 스크립트, 파서, 건너뛰기 | yt-dlp, faster-whisper, requests, selectolax |
| `index` | 청킹·임베딩·적재 | 자막 → 60초 청크 → bge-m3 dense+sparse → Qdrant `review_chunks`. 프레임 → SigLIP → Qdrant `frames` | 청킹, 메타 부착, 모델명·언어 태깅 | FlagEmbedding, transformers, qdrant-client, ffmpeg |
| `retrieve` | 검색 | 질문 → 모델명 추출 → 하이브리드(RRF) → 게시일 부스트 → 리랭크 → 인접 병합 → 문장 단위 링크 | RRF, 부스트, 병합, 문장 링크 | bge-reranker-v2-m3 |
| `specs` | 스펙 비교 | 모델 id 목록 → 정규화 스펙 표 + 차이 강조 | 정규화 스키마, diff | psycopg |
| `price` | 실구매가 | 모델 id, 통신사, 요금제 월액 → 경로별 24개월 총비용 + 계산식 | 전부 | psycopg |
| `vision` | 프레임 검색·OCR | 텍스트 질의 → 프레임 검색. 사진 → OCR → 모델명 매칭 → 확정/후보/모름 | 장면 추출 파이프라인, 매칭·확신도 | ffmpeg, SigLIP, OCR 라이브러리 |
| `generate` | 답변·검증 | 근거(한·영) + 표 → 프롬프트 → LLM → 인용 후처리 → NLI 검증 → 재생성 1회 | 프롬프트 조립, 인용 후처리, 문장 분리, 검증 루프 | requests, transformers(NLI) |
| `eval` | 평가 | 평가셋 → 지표 → `reports/날짜.md` | 지표 전부 | NLI, 교사 모델 |
| `finetune` | LoRA, 임베딩 | RAFT 데이터 합성, MLX LoRA 학습. 질문-청크 쌍 합성, bge-m3 추가 학습 | 데이터 합성, 학습 스크립트 | mlx-lm, sentence-transformers |
| `api` / `ui` | FastAPI / Streamlit | 12절 | 전부 | FastAPI, Streamlit |
| `framework` | 비교용 | LangChain + pgvector 파이프라인(여유 시) | | LangChain |

모든 모듈은 CLI로 단독 실행되고, 실행 가능한 체크 하나(테스트 또는 자체 점검)를 남긴다.

### 5.2 저장소

- Postgres: 정형(모델 사전, 스펙, 지원금, 전파인증, 리콜, 영상 메타, 피드백). 정확 조회는 SQL. ORM 없이 SQL 직접.
- Qdrant: 벡터. `review_chunks`(dense + sparse, payload: video_id, idx, start, end, text, lang, title, channel, published, model_ids), `frames`(SigLIP 벡터, payload: video_id, t, thumb_path).
- 원칙: 유사도는 벡터DB, 정확 조회는 SQL, 둘은 모델 id로 연결.

### 5.3 흐름

질문 흐름: 질문 → 모델명 추출 → [정형: `specs` + `price`] ∥ [비정형: `retrieve`(한·영)] → `generate` → 검증 → 답변 + 스펙·가격 표 + 영상 링크(영어 근거는 원문 발췌 + 한국어 요약).

시각 질의 흐름: "카메라 비교 장면" → `vision` 프레임 검색 → 프레임 썸네일 + 링크. 같은 영상·시각에 자막 히트가 있으면 가산.

사진 흐름: 박스·설정 화면 사진 → OCR → 모델 사전 매칭 → 확정이면 질문 흐름 합류. 후보면 사용자 선택. 못 읽으면 "라벨이 보이게 다시 찍어 주세요".

### 5.4 원칙

- 숫자는 LLM이 계산하지 않는다. `specs`·`price`가 만들고 LLM은 설명만.
- LLM 없이도 검색·스펙·가격·프레임·OCR은 동작한다.
- 확실할 때만 확정한다. 모델 확정과 답변 모두.
- 신형 질문에 구형 리뷰를 섞지 않는다. 게시일 부스트가 그 장치다.

## 6. 모델

### 6.1 LLM: Qwen 계열 (v1과 동일)

- Apache 2.0, 한국어·영어 모두 강함, MLX·Ollama 지원. 선정 시점의 최신 버전 중 mlx-community 4-bit 변환본이 있는 것.
- 교사 8~9B급 4-bit(데이터 합성, 베이스라인), 학생 4B급(서비스·LoRA 대상), 비전 설명·OCR 보조는 Qwen VL 소형(선택).
- 런타임은 MLX로 통일(`mlx_lm.lora`, `mlx_lm.server`). 2주차 베이크오프로 학생 크기 결정.

### 6.2 기타 모델

| 용도 | 모델 | 비고 |
|---|---|---|
| 텍스트 임베딩 | bge-m3 | 다국어. 한국어 질의 → 영어 청크 검색의 핵심 |
| 리랭커 | bge-reranker-v2-m3 | 다국어 |
| 이미지·텍스트 임베딩 | SigLIP | 프레임 색인과 텍스트 질의를 같은 공간에 |
| NLI | 다국어 xnli 계열, 4주차 후보 비교 | 영어 근거 ↔ 한국어 문장 판정이 되는지 확인 필요 |
| OCR | PaddleOCR 또는 EasyOCR(한·영), 7주차 샘플 비교 | 안 되면 Qwen VL로 읽기 |
| ASR | faster-whisper | 자막 없는 영상만 |

### 6.3 파인튜닝

| 대상 | 방법 | 결과물 | 필수 |
|---|---|---|---|
| 답변 LLM(학생) | RAFT: 근거(한·영 섞임) + 무관 청크를 주고 근거만 골라 한국어로 인용 답변하도록 LoRA. 2~3천 예제, 교사 합성 | 전후 환각률·인용 정확도·거절률·지연 | 필수 |
| 임베딩(bge-m3) | 합성 질문-청크 쌍 3~5천(평가셋과 분리)으로 대조 학습. 16GB라 fp16 + 작은 배치 + 상위 레이어만 학습 | 전후 Recall@5·MRR(한→한, 한→영) | 필수 |
| 백본·분류기 | 없음(v1의 차종 분류 헤드는 도메인 변경으로 제외) | | |

메모리: 서빙 시 학생 4B 4-bit 약 2.5GB + bge-m3 + 리랭커 + SigLIP + NLI 합쳐 7~8GB. 교사는 서빙 안 함. 색인·학습·서빙은 동시에 안 돌린다.

## 7. 검색 세부

1. 모델명 추출: 질문을 `models.yaml` 별칭(한·영)과 대조. 둘 이상이면 비교 질문.
2. 질의 임베딩: bge-m3 dense + sparse. 질의는 한국어, 청크는 한·영 섞임. dense가 교차언어를 담당하고 sparse는 같은 언어 안에서 정확 매칭을 담당한다.
3. 하이브리드: dense 상위 50 + sparse 상위 50 → RRF 직접 결합 → 상위 30.
4. **게시일 부스트**: 추출된 모델의 `release_date`가 있으면, 게시일이 출시일 이후인 청크는 가산, 출시일보다 6개월 이상 앞선 청크는 감산. 모델 id가 payload에 있으면 추가 가산. 필터로 강제하지 않는다.
5. 리랭크: 상위 30 → 상위 5(다국어 리랭커).
6. 인접 병합: 같은 영상 이어진 청크 합치기, 영상당 최대 2개. 한·영 채널이 섞이도록 언어별 최소 1개는 남기는 규칙은 두지 않는다(점수로만).
7. 문장 단위 링크: 청크 안에서 가장 맞는 문장의 첫 단어 시각. 링크 오차 목표 8초.
8. 실험 변수: dense / sparse / 하이브리드 / 하이브리드+리랭크 × 청크 길이 30·60·120초 × 부스트 유무.

## 8. 스펙 비교와 실구매가 세부

### 8.1 스펙 (`specs`)
- 정규화 필드: display_in, resolution, refresh_hz, chip, ram_gb, storage_gb(옵션 목록), battery_mah 또는 wh, weight_g, camera_main_mp, ports, os, launch_price_krw(옵션별), release_date. 원본은 JSONB로 보존.
- `compare(model_ids) -> 표`: 필드별 값과, 숫자 필드는 차이·우세 표시.
- 채점: 공식 페이지 값과 정확 일치(자동).

### 8.2 실구매가 (`price`, 폰만)
- 입력: 모델 id + 용량, 통신사(SKT/KT/LGU+/전체), 요금제 월액(사용자 입력; 지원금 표의 요금제 기준값을 기본으로 제안), 약정 24개월.
- 경로 A 지원금: 출고가 − 지원금(해당 통신사·요금제) + 요금제 × 24.
- 경로 B 선택약정: 출고가 + 요금제 × 0.75 × 24.
- 경로 C 자급제: 출고가 + 사용자 입력 알뜰폰 요금제 × 24.
- 출력: 경로별 24개월 총액, 월 환산, 계산식 문자열, 데이터 기준일. 지원금 데이터가 없으면 A는 "없음"으로 표시하고 B·C만.
- 채점: 스마트초이스 화면 케이스 10개와 정확 일치.
- 순수 함수 + 단위 테스트.

## 9. 비전 세부

### 9.1 프레임 검색
- 추출: ffmpeg 장면 전환 감지(임계값 0.3)로 프레임 저장, 최소 간격 5초, 영상당 최대 120장. 썸네일 320px.
- 색인: SigLIP 이미지 임베딩 → Qdrant `frames`(payload: video_id, t, thumb_path, channel, title).
- 질의: 텍스트를 SigLIP 텍스트 인코더로 임베딩해 같은 공간에서 검색. 한국어 질의는 SigLIP이 약할 수 있어 **질의를 영어로 번역(로컬 LLM)한 뒤** 검색하는 옵션을 두고 평가로 비교.
- 융합: 같은 video_id에서 |t − 청크 시각| < 30초인 자막 히트가 있으면 가산.
- 평가: 시각 질의 30개 수동 라벨(영상, 장면 시각) → ±10초 Recall@5.

### 9.2 모델 확정 (OCR)
- 사진 → OCR(한·영) → 텍스트 줄 → 모델 사전 별칭·모델번호와 퍼지 매칭 → 점수 임계값.
- 확정 1개 / 후보 3개(사용자 선택) / 못 읽음(재촬영 안내). 확실할 때만 확정.
- 평가: 직접 찍은 박스·설정 화면 20장 정확도.

## 10. 생성·검증 세부

- 프롬프트: 규칙(근거 안에서만, 모르면 모른다, 숫자는 표만 인용, 리뷰어 의견은 채널명 붙여 인용, **영어 근거는 한국어로 요약하되 원문 발췌를 그대로 인용 표시**) + 근거 청크 5개([1]~[5], 채널, 언어, 제목, 시각) + 스펙·가격 표 + 질문.
- 출력: 문장마다 [n]. 후처리로 유튜브 타임스탬프 링크.
- 호출: `mlx_lm.server` OpenAI 호환, 스트리밍, temperature 0.2.
- 검증: 문장 분리 → 인용 청크와 NLI(교차언어 포함) → 미지지 문장 표시 → 재생성 1회.
- 거절: 모델명 추출 실패 + 검색 최고 점수 임계값 미만 → "리뷰 데이터에 없음". 스펙·가격 없으면 항목별 "없음".
- 폴백: LLM 응답 없으면 근거 발췌 + 표만.

## 11. 평가

### 11.1 평가셋

| 대상 | 구성 | 규모 | 지표 |
|---|---|---|---|
| 리뷰 검색 한→한 | 합성 + 수동. 정답 구간 [시작, 끝] | 합성 150, 수동 30 | 겹침 Recall@5, MRR |
| 리뷰 검색 한→영 (교차언어) | 영어 청크에서 합성한 한국어 질문 + 수동 | 합성 100, 수동 20 | 겹침 Recall@5, MRR |
| 링크 정확도 | 위 전체 | | 링크 오차 중앙값(목표 8초), ±10초 적중률 |
| 스펙 비교 | 모델 쌍 케이스 | 20 | 공식 페이지 값과 정확 일치 |
| 실구매가 | 모델·통신사·요금제 케이스 | 10 | 스마트초이스 화면과 정확 일치 |
| 프레임 검색 | 시각 질의 수동 라벨 | 30 | ±10초 Recall@5 |
| OCR 모델 확정 | 직접 찍은 사진 | 20 | 확정 정확도, 확정률 |
| 답변 품질 | 수동 50 + 합성 100 + 모르는 질문 30 | | 환각률, 인용 정확도, 거절률, 지연 |

- 합성 질문: 청크 샘플 → 교사 모델이 "이 구간으로만 답할 수 있는 한국어 질문 하나, 모델명 포함"(영어 청크도 **한국어 질문**을 만든다). n-gram 겹침 필터. 시드 고정.
- 수동셋은 최종 보고 전까지 튜닝에 쓰지 않는다. 대표 숫자는 수동셋 기준.
- 자동 지표 검증: 답변 50개 수동 채점과 NLI 일치율.

### 12.2 UI (Streamlit)
한 페이지: 질문창, 사진 업로드, 통신사·요금제 입력, 답변 스트리밍, 근거 카드(채널·언어·제목·시각 링크·발췌), 스펙 비교 표, 실구매가 표(계산식 포함), 프레임 썸네일, 문장별 근거 배지, 신제품 레이더 탭, 피드백 버튼.

### 12.3 로컬 실행
docker compose: Postgres, Qdrant, api, ui. LLM은 `mlx_lm.server` 맥 네이티브. `.env` 하나. 사진 저장 안 함. 지연 목표: 검색 1초, 첫 토큰 2초, 전체 15초. 재현 `make setup / ingest / index / eval / up`.

### 12.4 배포 3층
v1과 동일. 1층(검색·스펙·가격·프레임·OCR, LLM 없음) 무료 호스팅, 2층 맥 터널 LLM, 3층 폴백.
