# 차봇 (carbot) 설계 문서 v1

작성일: 2026-09-09
상태: 사용자 검토 대기

## 1. 한 줄 정의

차 사진을 찍거나 차 이름을 말하면, 유튜브 리뷰어들이 뭐라 했는지(근거 링크 포함)와 월 유지비(공공데이터 계산)를 한 화면에 보여주는 로컬 RAG 서비스.

## 2. 목적과 제약

- 목적: AI 개발자 직무 포트폴리오. RAG, 벡터DB, LoRA 파인튜닝, 비전, 평가 리포트를 한 프로젝트에 담는다.
- 사용자 조건
  - 유료 AI API를 쓰지 않는다. 임베딩, 리랭커, LLM, OCR, 비전 전부 로컬.
  - 핵심 로직은 직접 구현한다. LangChain 계열은 5주차 비교 챕터에서만 쓴다.
  - RAG와 파인튜닝은 반드시 들어간다.
- 환경: M2 Pro 16GB, macOS. 기간 8주, 주 15시간.
- 재미 요건: 사용자의 취미(자동차·AI 유튜브)가 곧 데이터라 테스트가 놀이가 되어야 한다.

## 3. 범위

### 3.1 들어가는 것

| 기능 | 설명 |
|---|---|
| 리뷰 검색 | 유튜브 자동차 리뷰 자막을 타임스탬프 단위로 색인. 질문 → 근거 구간과 링크 |
| 유지비 계산 | 자동차세, 유류비, 보험 차량등급·기준가액, 리콜 이력. 공공데이터 기반 결정적 계산 |
| 차종 식별 | 사진 → 모델명. 확실할 때만 확정, 아니면 후보 3개 또는 "모르는 차" |
| 답변 생성 | 로컬 LLM이 근거와 계산 결과를 인용해 답변. 문장마다 근거 링크 |
| 환각 검증 | NLI로 문장별 근거 여부 판정. 근거 없는 문장 표시·재생성 |
| LoRA 파인튜닝 | RAFT 방식으로 학생 모델 학습. 학습 전후 환각률·인용 정확도 비교 |
| 평가 리포트 | 검색·계산·식별·답변 지표를 명령 하나로 마크다운 생성 |
| 배포 | LLM 없이 동작하는 1층을 무료 호스팅에 배포. LLM은 있으면 사용, 없으면 폴백 |

### 3.2 빠지는 것

- 신차 가격 비교, 중고차 시세, 보험료 금액 산출(개인차가 커서 등급만 표시).
- 100종 밖의 차종 식별(모르는 차로 처리).
- 자막 원문 재배포(로컬에만 저장, 결과에는 짧은 발췌와 링크만).
- 사진 저장(번호판 때문에 처리 후 즉시 폐기).

## 5. 구조

### 5.1 모듈

| 모듈 | 하는 일 | 입력 → 출력 | 직접 구현 | 라이브러리 |
|---|---|---|---|---|
| `ingest` | 수집 | 소스 → `data/raw/` JSONL·이미지. 이미 받은 건 건너뜀 | 수집 스크립트, 건너뛰기 | yt-dlp, faster-whisper, requests |
| `index` | 청킹·임베딩·적재 | 자막 → 60초 청크(오버랩 15초, 문장 경계) → bge-m3 dense+sparse → Qdrant. 이미지 → SigLIP → Qdrant | 청킹, 메타 부착, 모델명 매칭 | sentence-transformers, transformers, qdrant-client |
| `retrieve` | 검색 | 질문 → 모델명 추출 → 하이브리드(RRF) → 리랭크 → 인접 병합 → 문장 단위 링크 | RRF, 가산, 병합, 문장 링크 | bge-reranker-v2-m3 |
| `cost` | 유지비 | 모델 id, 주행거리, 유가 → 항목별 금액 + 계산식 문자열 | 전부 | psycopg |
| `vision` | 차종 식별 | 사진 → 임베딩 → 최근접 20 → 가중 투표 → 확신도 판정. 7주차에 분류 헤드 추가 | 투표, 확신도, 판정, 분류 헤드 학습 | transformers(SigLIP), PIL |
| `generate` | 답변·검증 | 근거 + 계산 결과 → 프롬프트 → LLM → 인용 후처리 → NLI 검증 → 재생성 1회 | 프롬프트 조립, 인용 후처리, 문장 분리, 검증 루프 | requests, transformers(NLI) |
| `eval` | 평가 | 평가셋 → 지표 → `reports/날짜.md` | 지표 전부 | NLI, 교사 모델 |
| `api` | FastAPI | 7개 엔드포인트 | 전부 | FastAPI |
| `ui` | Streamlit | 한 페이지 | 전부 | Streamlit |
| `framework` | 비교용 | LangChain + pgvector 파이프라인 (5~6주차) | | LangChain |
| `finetune` | LoRA | RAFT 데이터 합성, MLX LoRA 학습 | 데이터 합성, 학습 스크립트 | mlx-lm |

모든 모듈은 CLI로 단독 실행되고, 실행 가능한 체크 하나(테스트 또는 자체 점검)를 남긴다.

### 5.2 저장소

- Postgres: 정형 데이터(모델 사전, 연비, 리콜, 보험등급, 영상 메타, 피드백). 정확 조회는 SQL. ORM 없이 SQL 직접 작성.
- Qdrant: 벡터. 컬렉션 `review_chunks`(dense + sparse, 메타 payload), `car_images`(이미지 벡터, 모델 id·각도 payload).
- 원칙: 유사도는 벡터DB, 정확 조회는 SQL, 둘은 모델 id로 연결.
- 5주차 비교 버전은 pgvector를 벡터 저장소로 쓴다.

### 5.3 흐름

질문 흐름: 질문 → 모델명 추출 → [정형: `cost`] ∥ [비정형: `retrieve`] → `generate` → 검증 → 답변 + 유지비 표 + 영상 링크.

사진 흐름: 사진 → `vision` → 확정이면 질문 흐름 합류. 후보면 사용자 선택 후 합류. 모르는 차면 안내.

### 5.4 원칙

- 숫자는 LLM이 계산하지 않는다. `cost`가 계산하고 LLM은 설명만 한다.
- LLM 없이도 검색·계산·식별은 동작한다.
- 확실할 때만 확정한다. 차종 식별과 답변 모두.

## 6. 모델

### 6.1 LLM: Qwen 계열

- 근거: Apache 2.0, 한국어 강함, 0.6B~32B 라인업, MLX·Ollama 지원. 2026-08 기준 Qwen 3.5/3.8 계열까지 공개. 선정 시점에 mlx-community 4-bit 변환본이 있는 최신 버전을 고른다.
- 역할
  - 교사: 8~9B급 4-bit. RAFT 데이터 합성, 파인튜닝 전 베이스라인, 합성 질문 생성.
  - 학생: 4B급(또는 1.7B). 본 서비스 답변 모델. LoRA 대상.
  - 비전 설명(선택): Qwen VL 소형. 차종 후보 설명 문장용.
- 런타임: MLX로 통일. 학습은 `mlx_lm.lora`, 서빙은 `mlx_lm.server`(OpenAI 호환 API). Ollama와 설치된 gemma4:e4b는 2주차 베이크오프 비교 대상으로만 쓴다.
- 2주차 베이크오프: Qwen 1.7B·4B·8B급을 같은 30문항으로 돌려 지연시간·품질 표 작성, 학생 크기 결정.

### 6.2 기타 모델

| 용도 | 모델 | 비고 |
|---|---|---|
| 텍스트 임베딩 | bge-m3 | dense + sparse 동시 출력. 한국어 검증됨 |
| 리랭커 | bge-reranker-v2-m3 | |
| 이미지 임베딩 | SigLIP (CLIP과 1주차 샘플 비교 후 확정) | |
| NLI (환각 검증) | 다국어 NLI 모델 (예: mDeBERTa xnli 계열). 4주차에 후보 비교 | 사람 판정과 일치율 측정 |
| ASR | faster-whisper, 단어 단위 시각 옵션 | 자동 자막 없을 때만 |

### 6.3 파인튜닝

| 대상 | 방법 | 결과물 | 필수 |
|---|---|---|---|
| 답변 LLM (학생) | RAFT: 근거 청크 + 무관 청크를 섞어 주고 근거만 골라 인용 달린 답을 내도록 LoRA 학습. 데이터 2~3천 예제, 교사 모델로 합성 | 학습 전후 환각률·인용 정확도·거절률·지연시간 표 | 필수 |
| 차종 분류 헤드 | SigLIP 벡터 위 분류층 학습 | 최근접 투표 vs 분류 헤드 비교표 | 필수 |
| 백본 파인튜닝 | ConvNeXt-tiny 등 | | 시간 남으면 |
| 임베딩 파인튜닝 | bge-m3를 질문-청크 쌍으로 추가 학습 | Recall@5 상승 | 8주 이후 |

메모리: 서빙 시 학생 4B 4-bit 약 2.5GB + bge-m3 + 리랭커 + SigLIP + NLI 합쳐 7GB 안팎. 교사 8B는 서빙에 올리지 않는다. 색인·학습과 서빙은 동시에 돌리지 않는다.

## 7. 검색 세부

1. 모델명 추출: 질문을 `models.yaml` 별칭과 대조. 둘 이상이면 비교 질문.
2. 질의 임베딩: bge-m3 dense + sparse.
3. 하이브리드: Qdrant dense 상위 50 + sparse 상위 50 → RRF 직접 결합 → 상위 20. 추출된 모델 id가 메타에 있으면 가산(필터 강제 아님).
4. 리랭크: 상위 20 → 상위 5.
5. 인접 병합: 같은 영상의 이어진 청크는 합치고 영상당 최대 2개.
6. 문장 단위 링크: 청크 안에서 가장 맞는 문장을 다시 찾아 그 문장의 시각을 링크로 쓴다. 링크 오차 목표 때문에 필수.
7. 실험 변수: dense / sparse / 하이브리드 / 하이브리드+리랭크 × 청크 길이 30·60·120초.

## 8. 유지비 계산 세부

- 입력: 모델 id, 연간 주행거리(기본 15,000km), 유가(설정 기본값).
- 자동차세: 지방세법 배기량 구간별 cc당 세율 + 지방교육세 + 차령 경감. 전기차 정액. 수치는 코드 상수, 출처 조문 주석. 구현 시 조문으로 재확인(기억으로 쓰지 않음).
- 유류비: 주행거리 ÷ 연비 × 유가. 전기차는 km/kWh와 전기요금.
- 보험: 차량모델등급(1~21)과 기준가액만 표시. 금액 산출 안 함.
- 리콜: 건수, 최근 3건 제목, 리콜센터 링크.
- 출력에 계산식 문자열 포함. 순수 함수 + 단위 테스트. 위택스 자동차세 계산기와 케이스 대조.

## 9. 차종 식별 세부

- 색인: AI Hub 100종, 모델당 100장(각도·조명 골고루) → SigLIP → `car_images`. 모델당 20장은 평가용 홀드아웃.
- 흐름: 사진 전체 임베딩(크롭 없이 시작, 배경 문제가 보이면 검출기 추가) → 최근접 20 → 모델 id별 유사도 가중 투표.
- 확신도: 1위-2위 점수 차이, 1위 절대 유사도 두 조건.
  - 둘 다 통과 → 확정 1개.
  - 차이 작음 → 후보 3개 + 재촬영 안내.
  - 절대값 낮음 → 모르는 차.
- 임계값은 평가셋으로 정한다. "확정 시 정확도 95% 이상"이 되는 지점과 그때의 확정률을 같이 적는다.
- 7주차: 분류 헤드 학습, 최근접 vs 분류 헤드 비교. 모르는 차 판정은 계속 최근접 유사도로.
- VLM 보조(선택): 후보 3개일 때 설명 문장. 효과 없으면 뺀다.

## 10. 생성·검증 세부

- 프롬프트: 규칙(근거 안에서만, 모르면 모른다, 숫자는 계산 결과만, 리뷰어 의견은 채널명 붙여 인용) + 근거 청크 5개([1]~[5], 채널, 제목, 시각) + 유지비 표 + 질문.
- 출력: 문장마다 [n] 인용. 후처리로 유튜브 타임스탬프 링크 변환.
- 호출: `mlx_lm.server` OpenAI 호환 API, 스트리밍, temperature 0.2.
- 검증: 문장 분리 → 인용 청크와 NLI entailment 판정 → 근거 없는 문장 표시 → 재생성 1회.
- 폴백: LLM 응답 없으면 근거 발췌 + 유지비 표만 반환.

## 11. 평가

### 11.1 평가셋

| 대상 | 구성 | 규모 | 지표 |
|---|---|---|---|
| 리뷰 검색 | 합성 질문 + 수동 질문. 정답은 구간 [시작, 끝] | 합성 200~300, 수동 50 | 겹침 기준 Recall@5, MRR |
| 링크 정확도 | 위와 동일 | | 링크 오차 중앙값 (목표 8초 이내), ±10초 적중률 |
| 유지비 | 모델·주행거리 케이스 | 20 | 위택스 계산기와 정확 일치, 원본 API 값 대조 |
| 차종 식별 | AI Hub 홀드아웃 + 실물 사진 | 모델당 20장, 실물 30장 | Top-1, Top-5, 확정률, 확정 시 정확도 |
| 답변 품질 | 수동 50 + 합성 100 + 모르는 질문 30 | | 환각률, 인용 정확도, 거절률, 지연시간 |

- 합성 질문: 청크 샘플 → 교사 모델이 "이 구간으로만 답할 수 있는 한국어 질문" 생성(모델명 포함 강제). 청크와 n-gram 겹침이 큰 질문은 제외(필터 직접 구현). 시드 고정.
- 수동셋: 사용자가 진짜 궁금한 질문 50개, 정답 구간 직접 표시. 최종 보고 전까지 튜닝에 쓰지 않는다(홀드아웃). 대표 숫자는 수동셋 기준.
- 자동 지표 검증: 답변 50개를 손으로 문장별 채점해 NLI 판정과 일치율을 적는다.
- 교사 모델 유용성 점수(1~5)는 보조 지표. 한계 명시.

### 11.2 비교표 세 개

1. 검색 방식 × 청크 길이.
2. 파인튜닝 전후(학생 모델).
3. 직접 구현+Qdrant vs LangChain+pgvector.

### 11.3 운영

- 평가셋은 `data/eval/*.jsonl`로 git 관리.
- 평가 명령 하나가 전체 리포트를 `reports/YYYY-MM-DD.md`로 생성. 이력 누적.

## 12. 서빙·배포

### 12.1 API (FastAPI)

| 엔드포인트 | 역할 | LLM 필요 |
|---|---|---|
| `POST /ask` | 질문, 주행거리, 유가 → 스트리밍 답변 + 근거·유지비·검증 JSON | 있으면 사용 |
| `POST /identify` | 사진 → 확정/후보/모르는 차, 확신도 | 아니오 |
| `GET /cost/{model_id}` | 유지비 표 | 아니오 |
| `GET /search?q=` | 근거 청크 | 아니오 |
| `GET /health` | Postgres, Qdrant, LLM 상태 | |
| `GET /models?q=` | 모델 사전 검색(자동완성, 후보 선택) | 아니오 |
| `POST /feedback` | 좋아요·싫어요·이유 → Postgres | 아니오 |

### 12.2 UI (Streamlit)

한 페이지: 질문창, 사진 업로드, 답변 스트리밍, 근거 카드(채널·제목·시각 링크·발췌), 계산식 보이는 유지비 표, 문장별 근거 배지, 피드백 버튼.

### 12.3 로컬 실행

- docker compose: Postgres, Qdrant, api, ui.
- LLM은 `mlx_lm.server`로 맥 네이티브(Docker에서 MLX가 GPU를 못 씀). api는 `host.docker.internal`로 접근.
- 설정은 `.env` 하나. 비밀값 코드에 없음.
- 로그: JSONL로 질문, 청크 id, 단계별 지연, 검증 결과만. 사진 저장 안 함.
- 지연 목표(로컬): 검색 1초, 첫 토큰 2초, 전체 15초.
- 재현: `make setup / ingest / index / eval / up`.

### 12.4 배포 3층

| 층 | 내용 | 위치 |
|---|---|---|
| 1층 항상 | 검색, 유지비, 식별 | 무료 컨테이너 호스팅(HF Spaces Docker 또는 Fly.io). Postgres는 Supabase 무료 티어. Qdrant는 컨테이너 내 또는 Qdrant Cloud 무료 티어 |
| 2층 있으면 | LLM 답변 | 맥 `mlx_lm.server` + Cloudflare Tunnel |
| 3층 폴백 | `/health`가 LLM 다운 감지 → 근거 발췌 모드 자동 전환 | 코드 |

1층 CPU 리랭크가 느리면 끄는 옵션. 호스팅 업체는 8주차에 실제로 띄워 보고 확정.

## 13. 진행 방식

- 사용자가 직접 구현한다. Claude는 과제 카드(무엇·왜·완성 판정·힌트·함정)를 주고, 막히면 힌트, 그래도 막히면 함수 골격, 완성 후 리뷰.
- `docs/progress.md`에 완료·진행 중·다음을 기록. 세션 시작마다 읽는다.
- 한 번에 모듈 하나, 모듈 하나가 커밋 하나.
- 5주차 전 LangChain 금지.
- 색인·학습은 밤에.

### 13.1 깃 운영 (GitHub Flow)

- `main`은 항상 동작하는 상태. 깃 플로우의 develop·release·hotfix 브랜치는 쓰지 않는다(혼자 8주 프로젝트에 과잉).
- 과제 카드 하나 = 브랜치 하나. 이름은 `week1/ingest`, `week2/hybrid-search`처럼 주차/모듈.
- 끝나면 PR을 올리고 본인이 squash 머지한다. PR 본문은 `.github/pull_request_template.md`의 네 칸(무엇, 완성 판정, 측정치, 남긴 체크)만 채운다. PR 본문이 작업 일지이자 면접 기록이다.
- 주차 마일스톤마다 태그: `v0.1-week1` … `v0.8-week8`.
- 커밋 메시지 접두어: `feat:`, `fix:`, `eval:`, `docs:`, `chore:`. 규칙은 이게 전부.
- 설계 단계(이 문서까지)는 `main`에 직접 커밋했고, 1주차부터 브랜치·PR로 간다.
